# 面试答题模板库

把任何一个面试问题映射到固定骨架；用户已有草稿时改用精修模式。

## 素材来源（重要：不要自己重写题库）

本 skill 的**模板骨架**（T1–T17）是我维护的；**题目清单**和**STAR 范例**直接调用上游原件，不要复制正文进来：

| 上游文件 | 里面是什么 | 什么时候读它 |
|---|---|---|
| `vendor/interview-coach/references/questions.md` | 六类约 150 道真题：技术、行为、HR、行业、高级、应届 | 路由表匹配不到题型，或用户要"给我出几道题" |
| `vendor/interview-coach/references/star_examples.md` | 5 个完整 STAR 范例（领导力/解题/冲突/失败等） | T8 行为题要给示范，或用户说"给我看个例子" |
| `vendor/interview-coach/SKILL.md` | 上游原始说明（模拟面试/题库/答案精修/STAR 训练） | 需要理解上游能力边界时 |

上游来自 LobeHub「interview-coach」v1.0.4（面试答题类安装量第一，60 次），来源与许可证见 `vendor/PROVENANCE.md`。文件若缺失或过期，跑 `node scripts/fetch-vendor.mjs` 重新拉取；拉不到就只用自带路由表兜底，并告知用户。

## 两种模式

**A. 模板模式（默认）** —— 用户给题，要答案。输出固定六段，见下。
**B. 精修模式** —— 用户给了一段自己的回答，要改。结构直接沿用上游 §3 的四段（不改名）：

```
【Strengths】原话里哪句站得住，为什么
【Areas for Improvement】具体改哪里：缺数字 / 缺取舍 / 主语是"我们" / 太长
【Refined Version】改好的整段，可直接背
【Tips】这类题的通用规律，一句话
```

判定：用户消息里出现"我这样答行不行/帮我改/这段回答怎么样"→ 走 B；只给题目 → 走 A。

## 工作流

1. **判定模式**：A 还是 B（见上）。
2. **题目 → 模板**：查 `references/templates.md` 顶部「题型路由表」→ 得 T1–T17。
   - 路由表查不到：先到 `vendor/interview-coach/references/questions.md` 按关键词找最近的真题，再回映射到最接近的模板；仍无 → 用兜底四段骨架，并说明是兜底。
   - 一个题同时命中多个模板：按「主问什么」选一个主模板，另一模板只取结尾一句。
3. **收集事实**：只问缺的，最多 3 个（岗位/年限/一个带数字的成果）。没给就留 `【】` 占位，**不编造经历**。
4. **产出**：按对应模式的格式输出。
5. **自检**：过一遍三条硬规则 + 该模板的「扣分点」。

## 模板模式输出格式（六段，缺一不可）

```
【题型】T4 离职原因

【30 秒版】
<可直接背，80–110 字>

【2 分钟版】
<分 3–4 个短段，每段一个功能：锚点 / 证据 / 动机 / 回扣岗位>

【填空清单】
1. 【需要用户补的事实】
2. ...

【追问预备】
- 面试官可能追：<问题> → 一句答法：<话术>
- ...

【扣分点】
- <这题型最容易死的地方，1–3 条>
```

## 三条硬规则

1. **数字优先**：至少一个可验证数字（百分比/金额/人数/时长/排名）。没有数字就用对比（从 A 到 B）。
2. **"我"作主语**：动作句要能回答"你个人做了什么"，团队成果拆出你的份额。
3. **结尾回扣岗位**：最后一句落到"所以这个岗位/贵司"，不要停在自我陈述。

## 通用约束

- 中文口语，不写书面语、不排比，不用"赋能/闭环/抓手"。
- 30 秒版 ≈ 80–110 字；2 分钟版 ≈ 300–380 字。超了就是没控住。
- 不虚构经历。缺事实就明说"这里需要你补一个真实案例"。
- 薪资、离职原因、婚育等敏感题只给结构和边界，不诱导撒谎或隐瞒。
- 引用上游内容时保留其英文原句，不要中英混杂改写范例。
