# 识别与流式回答验证

这是引入语音临时预览和流式回答时的历史样本记录，不是每次版本更新后重新测量的性能承诺。

## 环境与方法

使用本机 RTX 4060 Laptop GPU、原有 Whisper large-v3-turbo q5_0 模型，输入此前下载的两段公开合成中英文混合语音。没有采集或保存用户语音，也没有使用真实 API Key 请求 DeepSeek。

下表按 PCM 音频时间线模拟分段，叠加本机实测 GPU 推理耗时。它衡量样本首次可见文字的估算时间，不是实际会议、UI 调度或公网网络延迟的基准。

## 样本结果

| 合成样本 | 修改前首次文字 | 修改后首次临时文字 | 修改前最终文字 | 修改后最终文字 |
| --- | ---: | ---: | ---: | ---: |
| CS_2，8.8 秒，含 Microsoft Word / WPS | 9.77 秒 | 4.30 秒 | 9.77 秒 | 9.43 秒 |
| CS_7，9.28 秒，含 Time Management | 10.39 秒 | 4.28 秒 | 10.39 秒 | 10.12 秒 |

这两段样本的最终文字与修改前一致，关键英文词保留。临时文字可能发生修订；只有完整语句的确认结果进入问题判断。仍保留最长 16 秒的正式语音上下文及边界重叠，较长连续讲话每约 4 秒显示一次临时结果。待处理任务增加时跳过可选的预览任务，正式音频不会因此丢弃。

停顿检测从 800 毫秒改为 500 毫秒；无回调时的收尾等待从 850 毫秒改为 550 毫秒，检查间隔从 250 毫秒改为 100 毫秒。正式文字稳定后的回答等待从 1500 毫秒改为 700 毫秒，UI 检查间隔从 500 毫秒改为 200 毫秒。音频或识别仍在进行时，继续等待完整内容。

自动与手动回答均接入真实 SSE 数据流，没有人工打字延迟。模拟 HTTP 流测试验证：完整响应结束前可见首段内容，中文 UTF8 跨字节与 JSON 转义正确，问题标记与 JSON 外壳不展示，取消可中止无后续数据的等待，异常或截断响应不会被标为完成。只显示答案内容，保留两分钟正文约束。

## 来源与局限

公开样本来源沿用[依赖来源清单](../依赖来源.json)中 `synthetic_smoke_test` 的记录；音频仅保留在本机测试工作目录，不放入 Git 或交付文件。

结果仅覆盖两段合成样本，不能据此推断真实会议的整体准确率，或不同口音、噪声及设备下的延迟。流式回答测试使用模拟 HTTP 流，不代表实际 DeepSeek 服务的首字或完整生成耗时，也未验证腾讯会议接收端的共享效果。当前输出上限为 700 字，属于后续功能规则，未纳入这次历史性能测量。
